# 持续目标任务（0.1.64）

用户明确要求长任务持续到验收通过时，机器人调用 `goal_start`，将目标和可执行验收命令保存到服务器。所有者也可通过 `POST /api/goal-tasks` 登记已有对话，以 `adoptJobs` 接管已有后台作业。普通问答不登记。

模型正常结束回复不会结束持续任务。服务器在原对话历史上恢复下一段，调度说明通过系统上下文注入，不伪造用户消息。原生工具批次续跑仍保留，本功能补齐批次之外的目标生命周期。

## 验收合同

每项包含 `id`、`title` 和 `check`。`check.tool` 为 `device_run_shell`，`args` 指定设备、实际命令及可选目录/超时，`stdoutIncludes` 为成功时必须存在的断言。命令必须读取真实产物或运行测试，不能只打印成功。合同登记后不可由目标工具修改。

`goal_verify` 执行检查，保存实际退出码和断言结果。`goal_finish` 重新执行全部检查，只有全部成功、没有在途设备调用和未完成后台作业才标记完成。模型不能直接提交 `passed`。

## 后台、离线和重启

- 后台 RPC 前保存启动意图，在命令首行附加 UUID 注释。重启后从设备作业列表对账，找回原作业，不盲目重启命令。
- 记录原设备和作业 ID，等待期间只查状态。设备离线等待重连；记录丢失则要求核实实际进程和输出文件后再决定下一步。
- 行锁、可续期租约、代次检查防止重复调度。每个进程最多同时调度两个任务，同一对话最多一个未完成任务。
- 回合结束而验收未完成时自动继续；无动作收尾退避至最多五分钟，提供商异常一分钟后重试。持续回合沿用用户权限，不继承普通定时回合的五分钟截止。

## 控制和权限

输入框旁固定宽度“任务 x/y”打开目标、逐项验收、作业和停止/恢复。原有聊天停止按钮同样生效：持久暂停，后台作业结束也不会唤醒；必须明确恢复。

审批和用户输入沿用原有流程，不自动批准。用户之间隔离；删除机器人、对话归档、撤权后暂停。`CHISABOT_GOAL_TASKS=0` 停止自动扫描并保留数据，默认开启，每三秒扫描。启动自动创建附加表和索引，PC/Android 无需重装。

## 验证

`server/tests/goal-tasks.integration.test.ts` 使用独立 PostgreSQL、真实子进程和临时产物，覆盖后台完成、提前收尾、验收失败、重启、停止/恢复、并发、在途验收停止、预 RPC 意图对账和权限隔离。CI 固定运行；上线另用真实模型与 PC 后台命令验收，不能以调用次数替代。
