# 长任务自动续跑（CB-099）

用户给出一个多步骤任务后，机器人在工具批次用尽时自动携带已有进度继续，不要求重复发送「继续」。完成并验证后输出最终答复；需要审批、登录或关键资料时等待用户。用户停止后不自动重启。

## 执行规则

- 原生服务端工具仍按普通 12 步、面板 20 步分批。移除工具结果里「步数快用完，停止调用工具」的提示。
- SDK 在批次边界以 `tool-calls` 结束，且本批新发起的工具都有结果、最后一组没有失败时，在同一个 run 内自动启动下一批。
- 续跑保留完整消息、状态、上下文、模型覆盖与 run 身份。用户消息和完成的工具不重放；SDK 仅放进模型 prompt 的审批结果继续保留，有结果的审批调用不再次执行。
- 对外开始 / 最终结束事件各一次；工具事件持续写入原有会话事件流，使用量包含所有批次，最后一次模型调用的上下文读数保持原语义。
- 后台 / 定时 / IM 的客户端工具接力移除原来的 30 段总上限。网页已有 SDK 每批 100 次前端工具的续跑逻辑保持不变。
- 正常最终答复不再续跑。停止、审批 / 接管等待、模型错误、最后一组工具失败不触发新的批次；未执行的前端工具交由其原有执行器处理。没有新工具进展时不会空转。

自动续跑解决工具批次造成的中断。提供方额度、上下文容量、具体工具失败以及服务重启仍按各自的错误或恢复机制处理；本次没有新增跨进程任务调度器。

## 代码

- `server/src/agents/tool-continuation.ts`：原生工具批次续跑、状态保留、终止判断与使用量。
- `server/src/copilot.ts`：工具分段配置、长任务指导、附件加载后接入续跑、克隆保留行为。
- `server/src/computer/headless-tools.ts`：无总段数上限的后台工具接力、取消结果禁止执行未完成工具。
- `app/src/lib/copilot/continue-agent.ts`：已有的前端 SDK 批次续跑。
